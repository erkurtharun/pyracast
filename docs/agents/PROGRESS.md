# Ideal-state program: progress

Resume point for the orchestrator after a context reset. Keep it short and current.

## Goal

Map every flow end to end, document it durably, then bring the codebase to its ideal
state (clean code, security, performance, resilience, ease of use). Five workflows run
in order: Stack → Flow map → Evaluate → Implement → Final scan. Each workflow ends with
an independent review (a Claude reviewer that did not write the work, plus Codex CLI).

## Ground rules for every agent

- Work on the local branch `ideal-state`. **Never push, never switch branches.** A push
  to `main` starts the production release (`GCP_DEPLOY_ENABLED=true`); the owner decides
  when that happens. Only the orchestrator commits.
- Never run `git clean`, `git reset --hard`, `git stash` or `git checkout -- <path>` on
  files you do not own. Other agents edit the same tree.
- Never touch `.env`, `secrets/`, `.dev/backups/`, `%LOCALAPPDATA%\pyracast\` or any
  PostgreSQL data directory. Do not start or stop the dev stack or PostgreSQL.
- Code, comments, docs, commit messages and agent output files are English. Locale
  files (`web/messages/tr`, `locale/tr`) stay Turkish.
- Take nothing at face value: cite `path:line` for every claim about the code and say
  which claims you did not verify. No agent approves its own work.
- Write details to the file named in your brief and return only a short summary.
- Database tests need their own database name so runs cannot collide: set
  `PGDATABASE=pyracast_<your-label>` for the run and drop every database you created
  when done. Use `--no-cov` for targeted runs; only the full `scripts/check.py` run
  measures coverage, and only the orchestrator schedules it.
- On Windows call PostgreSQL tools from PowerShell, not Git Bash, and never pipe or
  wait on `pg_ctl start` (the server inherits the handle and the call never returns).

## Working notes stay local

`docs/agents/work/` is git-ignored. The repository is public and production is live,
so candid defect and security observations are not published before they are fixed.
The notes are mirrored to `%LOCALAPPDATA%\pyracast\backups\agents-work\` at each
milestone; the final report summarises what was found and changed. Evaluation output
goes to `docs/agents/work/evaluation/` for the same reason.

Tools kept outside the repository: Mermaid validation
(`node <scratchpad>\mermaid-check\check.mjs docs`, Mermaid 11.17.2 in headless Chromium).
Codex follows the Turkish-explanations rule of `AGENTS.md`; ask it to answer in English.

## Owner decisions (2026-11-17)

- Pushing to `main` and the automatic production release on green CI are intended and
  stay. Consequence: everything merged must be production-safe. Schema changes are
  forward migrations that work on existing data; no migration squash or data reset
  that production cannot follow.

  When the program ends only `main` remains, locally and on the remote.
- Dependabot pull requests are resolved by best practice and merged, not left open.
- The old Temp cluster, the stray PostgreSQL on 55432 and the old `%TEMP%\pyracast-*`
  directories were deleted on request. RabbitMQ's directory was kept: it is in use.
